Safety Shields & Safeguards

Architectural security principles preventing system harm, rogue deletion, and file loss

Sudo / Admin Restriction Shield

ACTIVE

ZenMac is architecturally barred from running as root. If executed with sudo, the app will instantly shut down. Storage cleaners do not need root access; limiting privileges ensures that crucial system assets are never vulnerable.

Strict Whitelist-Only Scope

ENFORCED

The app only processes folders listed in its hardcoded whitelist. Unlike common utilities that crawl arbitrary directories, ZenMac does not have a code path capable of walking arbitrary system subdirectories.

Independent Blocklist Protection

VERIFIED

Every single path is checked against a strict blocklist before any operation. System assets inside protected locations (like /System, /Applications, ~/Documents, or ~/Desktop) are automatically blocked.

Reversible Trash-Only Method

PROTECTED

ZenMac completely avoids destructive shell commands like rm -rf. Instead, it calls Electron's native OS Trash integration. Cleaned assets are safely moved to Trash, allowing quick inspection and restoration.

Symlink & Realpath Validation

ENFORCED

Paths are resolved using fs.realpathSync() prior to checking blocklists to prevent symlink traversal tricks. If realpath resolution fails or encounters unresolvable paths, the safety function fails closed (blocked).

Zero Arbitrary Script Execution

ACTIVE

All cleaning actions pass through audited Node fs/Electron native IPC channels. No dynamic string commands or shell subprocesses are spawned during storage scanning or cleaning.
